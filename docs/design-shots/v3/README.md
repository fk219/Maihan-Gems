# Design audit v3 — develop's storefront on main

Generated by `apps/web/scripts/design-audit.mjs` against a production build
(`next build --webpack`) running with `DATABASE_URL` unset and
`SITE_URL=http://localhost:3100`:

```
BASE_URL=http://localhost:3100 \
OUT_DIR=../../../docs/design-shots/v3 \
WIDTHS=1440,768,390 \
node scripts/design-audit.mjs
```

Each capture records the HTTP status, axe-core results (WCAG 2.0/2.1/2.2 A+AA,
all violations, not only critical/serious), the number of colour-contrast
checks axe could not complete, and horizontal overflow in CSS pixels. The
machine-readable record is `audit.json`.

## What this run proves

- Every listed route answers **200** at 1440 / 768 / 390 (the 404 probe is the
  only route that may answer 404 and does).
- **Zero JavaScript page errors** in Chromium on every capture.
- **Zero horizontal overflow** at the three audited widths. Two responsive
  accommodations were needed: the desktop nav shows at >= 1366 px (the full
  nav needs 1366 px and overflowed 768–1365), the compare control is hidden
  at <= 420 px, the shop kind tabs wrap, and the DYO card grid is 2-up at md.

## What fails, honestly

The design is develop's, and so are its accessibility defects. axe still
reports serious findings; none was silently "fixed" by changing the design:

| Rule | Where | Why it is left |
|---|---|---|
| `color-contrast` | most catalogue pages: `#9A7B2C` eyebrow text and `#8A857B` meta text on the paper background | develop's palette. Darkening it would change the design the client asked for. Numeric fix if requested: `#7d5d10` for gold text. |
| `target-size` | the home variety rail (9 links) | develop's link blocks are smaller than 24×24 px. Enlarging them reflows the rail. |

`label-content-name-mismatch` was fixed (currency/language/bag aria-labels now
include their visible text), as were the missing document titles on the 404 /
demo / card-preview surfaces.

`incompleteContrast` counts are axe checks it cannot decide without a real
composite (gradient/image backgrounds). They are reported per capture in
`audit.json`, not treated as passes.

## Screenshot basis

The catalogue is **fixture-backed demo content**: main's locked database has no
product rows, so `lib/mgh/adapters/catalog.ts` falls back to develop's ledger and
every storefront page shows the "Demo content" chip. Prices, references and
availability in these images are illustrative, not inventory. Live catalogue
rendering is proven by the adapter unit tests, not by these captures.

Some client-side commerce surfaces (bag, checkout, lead forms, concierge)
probe `/api/fresh/*`, which is not implemented for those paths yet; with no
`DATABASE_URL` the compat layer answers 500 "API is not configured". That
request is recorded in `audit.json` for the three checkout captures. It does
not prevent the page from rendering (axe 0), and it is a backend gap, not a
design one.
